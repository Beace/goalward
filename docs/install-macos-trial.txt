Goalward — macOS trial installation guide

Supported devices
  Apple Silicon (M-series) or Intel Mac running macOS 13.3 or later.
  This package includes both arm64 and x86_64.
  The app itself requires no Node.js, Rust, Xcode, or development server.

Installation
  1. Double-click the DMG to open it.
  2. Drag Goalward.app into the Applications folder.
  3. Open Goalward from Applications, then eject the installation disk.
  If using the ZIP fallback, extract it and move Goalward.app into Applications.

macOS prompts on first launch
  This trial package is locally ad-hoc signed and has not been Apple-notarized.
  If macOS cannot verify the developer or Apple cannot check the app, first confirm
  that the file came from a sender you trust. After attempting to open it, go to
  System Settings → Privacy & Security, find the Goalward message, choose
  Open Anyway, and confirm the system prompts.
  An enterprise-managed Mac may disallow this action; contact the device administrator.
  If macOS reports malware or a damaged file, stop installation and contact the sender
  to verify the file again.
  Apple's official guidance: https://support.apple.com/en-us/102445

Connect an Agent Runtime
  First launch detects Codex, Claude Code, Kimi CLI, Pi, DeepSeek Harness, and existing
  model configuration installed for the current user. Import selected detection results
  or enter Manual setup.
  If a Runtime is not detected, follow its official installation and login instructions,
  then select Detect again.
  For a custom installation path, select the full executable path in settings and detect it.
  This app manages external CLIs and does not include these Runtimes, model weights,
  subscriptions, or API credentials.
  External Runtimes may have their own operating-system / Node.js version requirements.
  Launching from Finder does not read custom shell-profile aliases or environment
  variables exported only in a terminal. Prefer the Runtime's persistent login and
  configuration mechanisms.

Getting started
  Turn your direction into a goal, describe the expected result and evidence for judging
  progress, then break out the first task.
  When a task needs to read or write local files, select an existing directory, then choose
  a Runtime, model, and reasoning effort.
  Configure access under Settings → Runtimes, choosing read, write, and tool permissions
  as needed.
  Ordinary directories are supported; a Git repository is not required. Example tasks
  demonstrate the interface and do not execute real commands.
  After sending instructions, inspect the conversation, run status, execution details,
  and artifacts, then review results before deciding the next step.
  Codex / Claude Code / Kimi CLI / Pi have dedicated protocol adapters. Other generic
  CLIs require executable-path, argument, and input-method configuration.

Data and upgrades
  Chats, tasks, Runtime configuration, and execution records are saved locally for the
  current user under:
  ~/Library/Application Support/dev.goalward.desktop/
  Quit the old app before launching Goalward for the first time. Goalward preserves the
  previous data directory and attempts a migration without overwriting existing data.
  Older attachments may still reference the old directory; do not delete it prematurely.
  The installation package contains no sender chats, accounts, credentials, or local
  Runtime configuration.
  Updater-enabled versions check public GitHub Releases, including prereleases, at
  startup and every six hours.
  In Settings → App updates, check and download manually, stop Agents and save settings
  before installing, then restart the app. Downloads verify the update package and its
  version signature; this does not establish Apple notarization.
  Before updating, move the app into Applications and eject the DMG. An app cannot
  update in place on a read-only installation disk.
  Older versions without updates, such as v0.2.0, require one manual installation of an
  updater-enabled version first.
  You can also stop tasks, quit the app, and manually replace the old app in Applications.
  Uninstalling the app does not automatically delete the user data directory above.

File integrity
  The sender also provides SHA256SUMS.txt. Run this in the installation-package directory:
  shasum -a 256 -c SHA256SUMS.txt
  The checksum file and installation package must come from the same trusted sender.
